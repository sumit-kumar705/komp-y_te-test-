📋 STEPS TO DEPLOY TO RAILWAY:
─────────────────────────────────────────────────────────────────

1. PUSH THESE CHANGES TO GITHUB:
   ```bash
   git add .
   git commit -m "Fix Railway sleep state and optimize configuration"
   git push origin main
   ```

2. IN RAILWAY DASHBOARD:
   a) Go to your project settings
   b) Make sure these environment variables are set:
      - SECRET_KEY (random string)
      - JWT_SECRET_KEY (random string)
      - FLASK_ENV=production
      
   c) If using Railway's MySQL:
      - Add MySQL plugin from Railway marketplace
      - Railway will auto-set: MYSQLHOST, MYSQLUSER, MYSQLPASSWORD, etc.
      
   d) Settings → Deploy:
      - Start Command: (Railway should auto-detect from Procfile)
        gunicorn wsgi:app --workers 4 --bind 0.0.0.0:$PORT --timeout 120 --keep-alive 5 --log-level info --preload

3. REDEPLOY:
   - Railway will auto-deploy when you push to GitHub
   - Or click "Deploy" button in Railway dashboard

🔍 TROUBLESHOOTING:
─────────────────────────────────────────────────────────────────

ISSUE: App still sleeps
→ Make sure UptimeRobot is pinging /ping every 5 minutes
→ Check Railway logs for errors

ISSUE: Database connection errors on wake
→ Railway MySQL might be timing out
→ The new config.py settings should fix this
→ Check that MYSQLHOST environment variables are set in Railway

ISSUE: 502 Bad Gateway on first request
→ This is normal for cold start (app waking up)
→ Should resolve in 10-30 seconds
→ UptimeRobot will prevent this

ISSUE: Workers timeout
→ Check Railway logs
→ May need to reduce worker count in Procfile (--workers 2)

💡 RAILWAY TIPS:
─────────────────────────────────────────────────────────────────
